# Full Length Player 0.16.0-beta.5 — Network playback follow-up

- Shared speed changes no longer seek both videos again. They retain the existing positions, pause states, alignment and any pending shared seek.
- Network playback now asks MPV to build a three-second packet buffer before starting/restarting, rather than resuming with almost no headroom. This can add a short wait after seeking, in exchange for fewer immediate stalls. It cannot fix a persistently slow connection or CDN response.
- Diagnostics now include the beta build identifier, sync offset/drift, correction count, coordinated-seek state and cache refill setting. No media URLs, filenames or credentials are included.

The reported restore completed successfully, but both caches were nearly empty at 2x. This is a targeted buffering improvement, not a confirmed fix for every YouTube delivery issue. The existing correction loop already avoids correcting while MPV reports buffering; its behavior is retained.

Please restore the same 480p + Best available YouTube pair, let it play at 2x, then try speed toggles and a few seeks. If stalls continue, pause both for 15 seconds, resume, and copy diagnostics twice about ten seconds apart so we can compare buffers and correction counts. Report whether the pause helped.

Automated coverage exercises split video/audio over local HTTP, paused/playing speed changes and a speed change during a shared seek. Live YouTube CDN behavior still requires user testing. Stable v0.15.0 remains unchanged.

Buffer policy uses [MPV's documented cache-pause settings](https://mpv.io/manual/stable/#cache).
